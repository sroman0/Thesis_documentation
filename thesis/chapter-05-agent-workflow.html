Chapter 5 Agentic Writing Workflow

This document is the operational roadmap for rebuilding User-Space Runtime and Detection Implementation. Agent communication is HTML-first: every audit, synthesis and review must be a valid standalone HTML document that can be inspected in a browser, printed, and compared with the other handoffs.

Editorial Decision

The previous prose is not the new baseline. chapter5.tex has been reset to headings and stable labels. The committed draft remains recoverable from Git, but agents must rebuild claims from current code, tests and authoritative documentation.

Chapter 5 begins where Chapter 4 ends: a binary record has crossed the perf-buffer boundary. It explains how the Go runtime loads and owns the monitoring session, converts records into typed events, applies event scope, evaluates policies and detectors, and separates security output from operational logging. It does not repeat general eBPF theory, kernel hook implementations, system-design rationale or experimental results.

The current section plan is provisional. The synthesis agent may merge, rename or reorder sections when this removes repetition, but it must preserve the ownership boundaries below and provide a migration table for every changed heading or label.

Ownership Boundaries

MaterialPrimary ownerChapter 5 rule
General eBPF loading, maps, verifier, BTF and transport theory Chapter 2 Refer to it; explain only the concrete Go implementation.
Requirements, architecture, policy semantics and bounded-correlation design Chapter 3 Explain how those decisions are implemented, not why they were chosen again.
eBPF producers, hook families, binary writer and kernel compatibility Chapter 4 Start from the delivered record and avoid repeating C-side mechanics.
Go bootstrap, registry planning, decoding, admission, policy, detector, output and logging Chapter 5 Describe verified implementation mechanisms and their limits.
Functional tests, alert examples, CPU, memory, loss and detector quality Chapter 6 Cite tests only as implementation evidence; do not report evaluation conclusions.
Networking implementation and network detector rules Outside the authored contribution Exclude from the chapter and from coverage claims.
Non-negotiable constraints. Never use the internal tool name. Use British English. Describe deterministic rules, not machine learning or general anomaly discovery. Do not claim enforcement, cluster-wide correlation, Kubernetes integration, production readiness or a universal CPU result below five per cent.
