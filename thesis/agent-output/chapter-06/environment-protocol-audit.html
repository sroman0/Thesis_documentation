  • All Pods set hostPID: false, hostNetwork: false and shareProcessNamespace: false.
  • All Pods ran on the same node and therefore shared the node kernel observed by the monitor. This is node-local cross-Pod observation, not cross-node or cluster-wide correlation.
  • automountServiceAccountToken: false is set for all three roles.
  • The namespace uses the privileged Pod Security profile because the monitor is privileged; target and trigger remain hardened independently.
  • The monitor policy is included in its image, while the detector is delivered through a ConfigMap. The synthetic flag Secret is referenced only by the target Deployment.

4. Functional Protocol Timeline

  1. Create the dedicated namespace, detector ConfigMap and synthetic flag Secret.
  2. Apply target Deployment and Service, trigger Pod and monitor DaemonSet; wait for all resources.
  3. Capture effective manifests, Pod identities, IPs, cgroups, Service endpoint, security contexts and environment metadata.
  4. Confirm that target and trigger are separate Pods on the monitor's node and that Service traffic reaches the target.
  5. Confirm target UID 10001 telemetry and restore the canonical alerts-only, UID-filtered monitor configuration.
  6. Run three benign scenarios with unique run IDs and no automatic retry.
  7. Run three exploit scenarios with unique run IDs and no automatic retry.
  8. For every run, preserve client output, target and monitor intervals, Pod state before/after, diagnostics and metadata.
  9. Audit application outcome, expected evidence, alert count, loss diagnostics and restart delta as separate criteria.

The first benign run was delayed by a stale non-protocol connection from validation. This is preserved as an anomaly and its duration is excluded from performance interpretation.

7. Reproducibility Checklist

  • Environment, kernel, Kubernetes, Minikube and node runtime recorded.
  • Effective manifests, Pod identities, image identities, Service endpoint and cgroups preserved.
  • Commands and exit statuses recorded; operational scripts require a non-empty evidence directory.
  • Run IDs and before/after Pod snapshots preserved without automatic retry.
  • Archive the currently untracked laboratory, policy and evidence with immutable hashes.
  • Record the exact node CPU/memory capacity and allocatable values in the final archive if used numerically.
  • Keep the upstream revision and challenge checksums beside the cross-Pod campaign manifest.
