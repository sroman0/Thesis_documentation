Independent Technical, Statistical and Editorial Review of Chapter 6

Review date: 19 August 2026. Findings are ordered by severity and are based on regenerated values from the retained raw artefacts, not on the editorial synthesis.

Verdict

Changes required before first-draft acceptance. The chapter has a sound structure and its principal functional and performance observations are reproducible. It is not ready to circulate in its present form because both Chapter 6 figures contain material factual errors, and the prose misidentifies the ownership boundary of the measured cgroup CPU, memory and RSS values.

After those corrections, the chapter should be suitable as a bounded experimental evaluation. It already avoids general accuracy, loss-free, cross-node, enforcement and total-overhead claims. The approved length and visual budgets are respected.

Findings Ordered by Severity

High 1. The topology figure contradicts the applied experiment

Location: chapter6.tex:121-138; kubernetes-testbed-topology.drawio.png.

The figure does not contain the monitor Pod even though the caption says it shows the privileged monitor observing the node kernel. It labels two boxes as the AES-beta ClusterIP Service, although the final box is evidently intended to represent the mounted flag Secret. It also contains two boxes both labelled “Benign client”, one green and one red; the red one should be the exploit client. As drawn, the figure cannot support the cross-Pod topology claim and may cause the reader to infer a second Service instead of the Secret boundary.

Required correction: redraw it with four unambiguous elements: trigger Pod, ClusterIP Service, target Pod and monitor DaemonSet Pod on one node. Show the Secret only inside the target boundary, and show eBPF observation through the shared node kernel rather than through the Service path.

High 2. The exploit-flow figure uses the wrong flag and overstates client success

Location: chapter6.tex:171-188; ctf_exploitation_flow_II.drawio.png.

The lower panel says that receiving THESIS{...} proves client-side success. The cross-Pod raw runs recovered openECSC{ebpf_cross_pod_evaluation}, and the client harness accepted only one of three exploit outputs because the first two checks used defective patterns. The figure therefore conflicts with both the dataset and the chapter's own oracle separation. It also calls the flow an event sequence without displaying the four logical event names or distinguishing LSM mediation from the successful open return.

Required correction: use a neutral “synthetic flag recovered” label, separate application recovery from client validation, and map the final command to the four observed events with their evidential boundaries.

High 3. CPU, memory and RSS are attributed to the wrong measurement owner

Location: chapter6.tex:48, 312-316, 327-389, 434-436, 469-470.

The sampler resolves the monitor container ID and reads cpuacct.usage, memory.usage_in_bytes and memory.stat from the matching container cgroup. These are not Pod-cgroup counters. Moreover, “process RSS” is incorrect: the reported RSS is the cgroup-v1 total_rss field, not a process value read from /proc. The current terms “monitor Pod's cgroup” and “resident memory of the monitor process” materially misstate what was measured.

Required correction: consistently use “monitor-container cgroup CPU”, “monitor-container cgroup memory usage” and “monitor-container cgroup total_rss”. Apply the same correction to the target metric. Retain the existing qualification that eBPF kernel execution charged elsewhere is excluded.

Medium 1. The 91.97% reduction is calculated from rounded aggregates

Location: chapter6.tex:386-389, 455-456, 469-470.

The archived summariser first rounds profile means to 0.46 and 5.73, then computes (5.73 - 0.46) / 5.73 = 91.97%. Regeneration from the raw run-window samples gives means of approximately 0.45697 and 5.73178, producing 92.027%, or 92.03% at two decimals. Computing a two-decimal effect from already rounded inputs introduces avoidable precision error.

Required correction: recompute before rounding and report “approximately 92.0% lower” or 92.03% with the precise formula and monitor-container cgroup denominator.

Medium 2. Causal language exceeds the experimental control

Location: chapter6.tex:380-384, 401-409.

The text says the comparison “attributes” the reduction to early rejection and that filtering “reduced” CPU. The mechanism is plausible and the observed difference is large, but profiles were executed sequentially on a node averaging about 94% CPU, with three runs per profile and uncontrolled background load. Rotated ordering limits simple order bias but does not establish full causal control.

Required correction: state that enabling exact UID admission was associated with the lower monitor-container CPU in this campaign and that the result is consistent with early rejection reducing transport and user-space work.

Medium 3. Not every CPU percentage states its denominator and boundary

Location: chapter6.tex:48-49, 312-321, 366-368.

Monitor CPU is correctly expressed as a percentage of one core, but target CPU is not explicitly defined as target-container cgroup CPU with the same one-core denominator. Node CPU is a different construct: the busy fraction of aggregate node CPU jiffies across the two CPUs. The prose lists all three percentages without defining these two denominators.

Required correction: define target CPU and node CPU separately before reporting percentages. Do not place them under a shared “CPU percentage” description.

Medium 4. The live negative controls are too narrow for detector-quality implications

Location: chapter6.tex:244-294, 420-458.

The three benign repetitions execute the same encryption interaction. They are repetitions of one control, not three distinct benign behaviours. No live case tests wrong event order, shell without flag access, access to a different file, a failed final open, UID mismatch, parent-child correlation or expiry after five seconds. The chapter already rejects a false-positive-rate claim, but the threats section should explicitly identify these missing near-miss controls.

Medium 5. The evidence package is not versioned or immutably archived

Location: reproducibility claims at chapter6.tex:52-58 and the underlying repository state.

Both authoritative datasets, the cross-Pod manifests and the sampling scripts are under an untracked directory. The datasets record the Git commit, but a checkout of that commit cannot reproduce or independently inspect the experiment. The chapter's “supports repeatability within this laboratory” wording is defensible only if this external bundle is preserved with stable hashes and submitted beside the thesis.

Medium 6. Metric sampling has an unreported edge-window limitation

Location: chapter6.tex:306-321.

Samples are one-second deltas and are selected when their ending timestamp falls between workload start and end. The first accepted delta can include a fraction before workload start, while work after the final accepted sample and before workload end is not represented. This is small relative to 41-58 second runs but should be recorded as a measurement limitation, especially because sample counts differ from 38 to 52.

Low 1. Some discussion and summary prose repeats earlier chapters or restates results

Location: chapter6.tex:393-418, 461-476.

The explanation that filtering before transport avoids unnecessary user-space processing repeats the architecture rationale owned by Chapters 3 and 4. The final summary then repeats the exact functional and performance values already stated in the results and discussion. This is not severe, but the discussion can focus on interpretation and the summary can be shortened to the three bounded conclusions.

Low 2. The chapter has unresolved citation and typesetting issues

The citation used for hostPID describes sharing a process namespace between containers in one Pod, not the PodSpec hostPID field. The AES-beta bibliography URL points to the repository's main branch despite the prose claiming a pinned revision. Cgroup-v1 memory and /proc/stat node CPU semantics lack primary citations. The first use of TCP is not expanded or linked to a glossary entry.

Isolated parsing also reports a 30.53 pt overfull line around the long sched_process_exec name at lines 221-228 and a 5.44 pt overfull table header around line 274. These should be broken or reformatted before final layout review.

Citations, Glossary, Labels and LaTeX

  • All seven Chapter 6 citation keys exist in bibliography.bib.
  • All Chapter 6 figure/table references have matching labels, and no duplicate Chapter 6 labels were found.
  • British-English usage is consistent; no material American spellings were found.
  • The glossary contains CPU, CTF, RSS, UID, GID, SD and ATT&CK. TCP should be expanded at first use or added as an acronym.
  • kubernetes_process_namespace is not the best source for hostPID; add the official PodSpec/API field documentation.
  • Pin the openecsc2024_aes_beta bibliography URL to revision 2602f22c664eb98398413e6a7dfe03ea88b2d296, not the moving main branch.
