Executive Findings

  1. The implemented analytical path is deterministic and rule based. No baseline learning, statistical score, contextual anomaly model or cluster-wide correlation is present.
  2. Committed policies load and validate event scope, compile exact event allowlists when possible, and perform event-time admission. They do not select detector definitions in committed HEAD.
  3. Policy-driven detector selection by ID, severity, tags, statefulness and ATT&CK metadata exists only in the dirty worktree. It parses the whole catalogue first and instantiates only selected definitions.
  4. The detector engine builds an event-name dispatch index. An event-time failure in one detector is isolated and does not stop other candidate detectors.
  5. Collective detectors retain one partial sequence per detector and correlation key. State is bounded by a maximum five-second window and 4096 partial keys per detector.
  6. Process, immediate-parent, file-resource, cgroup and conjunctive composite correlation are committed. user_session is recognised but rejected.
  7. Flush() can force expiry in tests and through the engine API, but the main runtime loop never invokes it. Idle stale state therefore disappears on later qualifying detector traffic or capacity eviction, not through a runtime timer.
  8. Alert deduplication uses a fixed five-second processing-time window. Its cache is time-pruned but has no capacity bound; collective-alert identity uses only the first evidence event.
  9. ATT&CK identifier validation is syntactic only. Empty mappings are allowed, names and framework versions are not checked against a catalogue, and mapping quality remains an authoring and evaluation concern.

Bootstrap Versus Event Time

Bootstrap pipeline

1. LoadRead policy and detector YAML from explicit files or non-recursive directories.
2. ConvertMap external schemas to normalised policy and detector definitions.
3. ValidateCheck modes, events, operators, windows, correlation plans and metadata syntax.
4. CompileCompile exact event scope, conditions, steps, correlation components and dispatch indexes.
5. ConstructCreate one policy manager and one shared detector engine with detector-local state.

Policy directories are sorted lexically within each supplied policy path; the outer path order is preserved. Detector files from all supplied paths are globally sorted before parsing, and the registry subsequently orders detector instances by ID. Directory traversal is non-recursive. Both YAML loaders use ordinary yaml.Unmarshal, so unknown YAML keys are silently ignored rather than rejected as schema errors.

Detector bootstrap compiles operators, comma-separated membership lists, numeric constants, ordered steps and correlation strategy names. Event-time processing therefore does not reparse YAML. In the dirty selector path, all detector documents are still parsed and validated before selection; an invalid detector outside the selected subset can therefore fail startup.

Event-time pipeline

decoded event
  -> configured event-name admission
  -> command-name admission
  -> policy manager (scope + rules; suppress wins)
  -> optional raw-event presentation
  -> event-indexed detector dispatch
  -> point predicates OR collective state transition
  -> alert evidence + ATT&CK metadata
  -> five-second alert deduplication
  -> optional alert presentation

The same bufferdecoder.Event value is supplied to policy and detector matching. Policy mode is not used to create separate event-time branches: monitor and detect both admit matching events, while any matching suppress policy rejects the event before raw output and detector dispatch. Consequently, a detector can run on an event admitted only by a monitor-mode policy.

Policy semantics and validation details

  • Empty policy mode defaults to monitor; empty intent defaults to threat_hunting.
  • Empty scope lists mean no restriction. Policy rules compose through OR; fields inside one rule compose through AND.
  • An empty event include list means all events. Exclusion wins within a rule.
  • Allow policies compose through union. A matching suppress policy overrides all matching monitor or detect policies.
  • Argument filters support only args.name=value and args.name!=value, with simple leading or trailing wildcards. Malformed or non-args. filter strings are silently discarded by the loader.
  • Policy names need not be unique, rule names may be empty, and the package-level validator does not verify event names. The command bootstrap performs event-registry validation.
  • Exact early event selection is unavailable when any non-suppressive rule has an implicit all-events selector. In that case the broader configured collection scope is retained.

Dirty detector-selection semantics

  • Values within one metadata field use OR; different populated fields use AND.
  • Selections from multiple policies are unioned. Exclusion is local to one policy and cannot remove a detector selected by another policy.
  • An empty include criterion matches the whole available catalogue; an explicit selector matching nothing is an error.
  • Explicit include and exclude IDs are checked against the catalogue loaded from the CLI paths.
  • The event-consistency check uses Definition.EventNames(), so optional requirements are also required to be admitted by the selecting policy. This is stricter than the word “required” suggests.
  • If a policy contains a detector selector but no detector catalogue is configured, event-policy behaviour remains active and selection is skipped with a warning.

Point Detector Semantics

The dispatcher calls only detectors indexed for the current event, plus any wildcard detector whose definition declares no events. A point detector first applies all top-level conditions. If it declares steps, the current event must also match one step and that step's conditions. A successful match immediately creates one alert containing the source event.

Supported operators are equality, inequality, substring containment, exact membership, prefix, suffix, existence, non-existence, greater-than and less-than. Operators and expected numeric values are compiled at construction. A non-numeric actual value supplied to a numeric comparison produces a detector-local error rather than a no-match result.

Schema gap. The parser does not require a detector with multiple steps to set stateful: true. A non-stateful multi-step definition behaves as a point detector and may alert on any matching step. Likewise, a stateful detector with zero or one step uses the stateless path. Chapter 5 should describe the valid rule convention and record the missing cross-field validation as a limitation.

Collective Detector State Machine

  1. Admission. The event must be indexed for the detector and satisfy every top-level condition.
  2. Key construction. The compiled correlation plan creates one or more candidate keys. Missing required components produce no key and therefore no state change.
  3. Expiry check. Global pruning runs only when its scheduled deadline is reached; the candidate state addressed by the event is checked directly on every lookup.
  4. Advance. For each lookup key, the event is compared with the next expected step. A match appends the event and advances exactly one step.
  5. Complete. Matching the final step removes the partial state and returns one alert containing the ordered evidence.
  6. Start or restart. If no state advances and the event matches the first step, one state is stored under the current-process/composite start key. A repeated first step for the same key replaces the previous partial sequence and resets its window.
  7. Ignore. A relevant event that matches neither the next step nor the first step leaves existing non-expired state unchanged. Sequence events need not be contiguous in the complete input stream.

There is one partial sequence per key, not a branching set of alternative matches. Sequence time is measured from the first matched event using the detector's processing clock, and expiry uses a strict greater-than check; completion exactly at the configured window remains eligible. Arrival order is used as received from the runtime. The engine does not reorder events or infer causality across perf-buffer CPUs.

Collective expiry normally occurs while a stateful detector processes an indexed event that passes its top-level conditions. Explicit Flush(now) forces a full expiry scan and reschedules pruning, but production runtime integration is absent. Timeouts do not generate alerts.

The deduplication key includes detector ID, alert title, severity and fields from the first evidence event: event name, namespace PID, UID, command and ordered arguments. It ignores timestamps, thread IDs, process start time, threat metadata, later collective events and the correlation key. Thus it is an alert-noise control, not a uniqueness or causal-identity guarantee.

ATT&CK Handling

  • Detector definitions may be unmapped; ATT&CK metadata is optional.
  • Tactic IDs must match TA plus four digits. Technique IDs must match four digits with an optional three-digit sub-technique suffix.
  • Empty IDs inside tactic or technique entries are accepted. Framework, version, names, data sources and data components are not semantically validated.
  • A detector alert receives a copy of the complete threat metadata from its definition.
  • The dirty policy selector can match tactic and technique IDs after uppercase normalisation. It uses only local detector metadata and no downloaded ATT&CK dataset.
  • Chapter 5 may describe metadata propagation and syntactic validation. Mapping correctness and coverage belong to Chapter 6.

Chapter 3 claims requiring correction or qualification

  1. Policy selection of detector definitions is described as current architecture, but it is not committed at the inspected HEAD.
  2. The statement that unsupported correlation dimensions are rejected at bootstrap is too broad. This is explicit for user_session and schema-checked for resource; missing process or cgroup identity is handled as a runtime no-match.
  3. The statement that state expires when “detector state is flushed” is true at API level, but the production loop does not schedule flushes.
  4. The alert-deduplication description should not imply complete collective equivalence: the key ignores all evidence after the first event.
