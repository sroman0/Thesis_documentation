1. Binding Editorial Position

Chapter 5 begins when a perf-buffer record produced by the kernel-side implementation is delivered to Go. It explains how the user-space runtime resolves inputs, plans physical probes, decodes the binary record, admits the resulting event, evaluates policies and detectors, renders alerts and diagnostics, and packages the executable. Chapter 4 remains the owner of hook programs, event construction, the binary writer, perf submission and kernel compatibility branches. Chapter 6 remains the owner of observed behaviour, coverage, performance and functional results.

The central implementation claim is deliberately narrow: one schema-directed decoder produces a typed bufferdecoder.Event that is shared by policy matching, detector dispatch and output adapters. Admission gates then decide whether the event is presented or analysed. This is deterministic rule evaluation, not baseline learning, statistical anomaly scoring, contextual anomaly inference or cluster-wide correlation.

Baseline rule. The selector for detector definitions and the corrected project constructor are present in d916df7. The local corrections that classify raw_sys_enter and security_socket_sendmsg as internal, reject an empty policy/CLI event intersection, and surface cleanup errors are not yet in that commit. They may be described as final behaviour only after they are committed; before then they belong in a limitation or implementation note.

11. Terminology and British-English Rules

  • Use “the proposed tool”, “the prototype” or “the monitoring agent”; never use the internal project name in thesis prose.
  • Use user space as a noun and user-space as an adjective. Use normalised, catalogue, behaviour and containerisation.
  • Reserve normalised event for bufferdecoder.Event. Call the output-layer object a presentation or serialisation model.
  • Keep event, policy, detector, alert, logical event, physical probe and internal support probe distinct. Do not use hook and event as synonyms.
  • Use perf buffer for the active transport and BPF ring buffer only for background or future work.
  • Say point detector and collective detector; use point anomaly or collective anomaly only when discussing the observation taxonomy.
  • Describe local cgroup and file identities as kernel-local correlation keys, never as Kubernetes workload identities.
  • Use “MITRE ATT&CK tactics and techniques”. Metadata classifies alert intent and improves traceability; it does not establish correctness, coverage or novelty.
  • Use “compact text output” in prose; retain “table” only when quoting the CLI format name.

  • All numerical limits appear primarily in 5.4.3 or the decoder table, not repeatedly in detector examples.
  • The text states that collective expiry is event-driven in the integrated loop because no runtime flush timer is wired.
  • The text distinguishes committed code from the three local corrections until those corrections are committed.

  • Networking content is excluded except for a narrowly scoped lifecycle dependency.

The chapter is strongest when it tells one continuous ownership story: configuration and probe planning acquire the runtime, decoding gives the record meaning, admission controls its consumers, detectors preserve local evidence, and output/logging expose separate results.
