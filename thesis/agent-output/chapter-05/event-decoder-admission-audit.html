Record-to-Admitted-Event Pipeline

1. Perf delivery. During initialisation, libbpfgo opens one reader over the events perf-event array and delivers record byte slices and loss counts on separate Go channels.
↓
2. Runtime receive. Project.Run selects a raw byte slice from perfBufChannel. Debug accounting may note the first raw record; no event interpretation has occurred yet.
↓
3. Decoding begins. handleRawEvent calls bufferdecoder.DecodeEvent(raw). This call is the first interpretation of host-event bytes.
↓
4. Fixed context. The decoder reads the explicit 136-byte context, then the one-byte declared argument count.
↓
5. Schema-directed arguments. The numeric event ID selects an event specification. Each encountered index selects the corresponding argument name and decoding type. Successfully decoded arguments are returned in schema order.
↓
6. Decoded event. The result is one bufferdecoder.Event containing the context, public logical-event name and typed arguments. Host events require no second normalisation object.
↓
7. Runtime admission. The event must pass, in order, the selected-event set, the optional exact command-name filter, and the policy manager. A rejection returns immediately.
↓
8. Independent consumers. Unless alerts-only is set, the event printer receives the admitted event. The detector engine receives it regardless of alerts-only. Detector alerts then use the independent alert printer.

Optional socket or network enrichment occurs after decoding and before admission, but it is outside this host-event audit. It must not be described as the general normalisation stage.

Fixed Event Context

bufferdecoder.EventContext is the explicit Go mirror of the fixed C context. DecodeContext reads fields by fixed little-endian offsets instead of relying on Go struct layout or binary.Read. The contract covers timestamp and task start times, cgroup identity, process and thread identities in observed and host namespaces, UID, namespace IDs, fixed command and UTS-name arrays, event ID, syscall number, stack and CPU identifiers, and policy metadata. Its declared wire size is 136 bytes.

This explicit-offset approach makes the wire layout visible and avoids Go padding assumptions, but the size constant and field offsets remain manually synchronised with the C structure. There is no automated cross-language layout generator or compile-time C/Go assertion in the inspected packages.

Schema-Directed Argument Decoding

The wire record carries an argument index but no independent type tag. The index is looked up in pkg/events/spec.go; its registered DecodeAs value determines how many bytes are consumed and which Go value is produced. This means that a valid event is schema-compatible in the practical sense that every encountered index can be decoded using the registered schema. It does not mean that the producer's intended type can be verified independently from the schema.

Implemented host payload families include:

  • fixed-width booleans and unsigned or signed integer and pointer values;
  • length-prefixed strings and byte slices;
  • bounded arrays of length-prefixed strings;
  • compact NUL-delimited argument arrays with payload length and reported count;
  • fixed-width compact credential snapshots; and
  • socket-address records, whose protocol-specific audit is outside this report.

Strings have trailing NUL bytes removed and are checked for valid UTF-8. Missing schema fields are permitted because eBPF collection can omit an unavailable argument while preserving the indexes of later fields.

The most accurate claim is that the decoder provides bounded, schema-directed typed interpretation. It does not currently enforce a unique canonical encoding because missing fields, duplicate indexes and trailing bytes are accepted, and declared argument count is not always satisfied strictly.

Registry Authority and Invariants

There is no single registry for both semantics and attachment. The event registry is authoritative for the public userspace decoding contract; the probe registry is authoritative for attachment and CLI selection. Their relationship is many-to-one where several physical programs produce one logical event. Internal probes are physical dependencies without a public decoded-event contract.

What Normalisation Means Here

Precise answer. For runtime events, decoding is the normalisation boundary. bufferdecoder.DecodeEvent converts a raw perf record into the common typed representation consumed by both policy matching and detectors. It resolves the logical event name, maps indexed payloads to schema names and Go types, orders present arguments by schema, trims string terminators, and validates text and configured bounds.

The policy layer constructs a small policy.EventInput containing the event name, command, UID and a pointer to the same decoded event. This is an admission view, not a second event normalisation stage. The detector type is a direct alias of bufferdecoder.Event, so detector dispatch receives the same model without conversion.

pkg/output/event.go creates a separate user-facing JSON record, groups context fields and adds symbolic labels. Its comment also uses the word “normalized”, but architecturally this is presentation adaptation. It occurs only when an admitted event is printed and is not the representation consumed by policy or detector logic. Chapter 5 should reserve normalised event for the decoded bufferdecoder.Event and call the output structure a presentation or serialisation model.

Loss, Malformation and Processing Errors

  • Lost records are counts received from libbpfgo's separate loss channel. Zap emits a warning; no bytes exist to decode.
  • Malformed records reached user space but failed DecodeEvent. Zap emits a decoding error with available ID/name and record size; processing continues with later records.
  • Filter rejections are valid decoded events deliberately stopped by runtime admission. At debug level, only the first five drops are logged.
  • Detector errors occur after admission and are logged independently. Other detector results for the same event remain available.
  • Presentation errors are logged after decoding and admission and do not turn the event into an alert or terminate the loop.
  • Closed perf or loss channels end Run without an error; this is a lifecycle termination path, not malformed input.

Unresolved Contract Risks

  1. Registry correction must be committed. The current local changes mark support-only raw_sys_enter and security_socket_sendmsg as internal, and the complete package test suite passes. The clean commit still fails until these changes are included.
  2. Cross-language event IDs. C and Go event constants are manually maintained. Existing registry tests remain entirely in Go and cannot detect a numeric mismatch emitted by eBPF.
  3. Cross-language context layout. The 136-byte layout is explicit and tested indirectly through decoding, but no generated ABI or C/Go compile-time comparison prevents one side from changing alone.
  4. Argument-schema drift. No wire type tag exists, and tests do not compare every C write index and width against every Go argument specification. Same-width semantic mismatches may decode without error.
  5. Non-canonical records. Duplicate indexes overwrite, trailing bytes are ignored, and an overstated argument count can be accepted when the stream ends between records. Decide whether this permissiveness is intentional before presenting it as a stable public contract.
  6. Validation coverage. Unknown IDs, invalid indexes, short contexts, short scalars, oversized payloads, duplicate indexes, missing arguments and trailing bytes need focused regression tests.
  7. Hot-path integration coverage. There are no direct tests proving admission order, filter short circuits, alerts-only behaviour, or continued processing after malformed input and presentation errors.
  8. Registry exception pressure. The network selector exception means “every public probe has a same-named decoder event” is not universally true. Chapter wording should qualify the invariant instead of hiding the exception.
  9. Merge regression in internal classification. The previous merge temporarily exposed raw syscall and socket-send support probes as public. The current working tree restores the correct boundary; the remaining risk is version drift until it is committed.
  10. Terminology ambiguity. pkg/output/event.go calls its JSON view “normalized”. Reserve architecture-level normalisation for bufferdecoder.Event and describe the output record as a presentation model.

Editorial Conclusions

The central Chapter 5 claim can be supported: one schema-directed decoder produces the typed host-event model shared by policy and detector logic, after which explicit admission gates control both presentation and analysis. The chapter must pair this claim with the decoder's actual permissiveness and the remaining manual C/Go synchronization risks.

The current Chapter 3 wording is mostly accurate, including its qualification that decoding is bounded rather than canonical. Chapter 5 should deepen that account through concrete ownership and tests, not repeat the architectural narrative. Before synthesis, the current probe-registry and runtime-lifecycle changes should be committed so the implementation evidence refers to one coherent, passing revision.
