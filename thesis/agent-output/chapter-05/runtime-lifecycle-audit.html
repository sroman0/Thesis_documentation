End-to-End Bootstrap Sequence

  1. cmd/project/main.go invokes the Cobra command and converts a returned error into a non-zero process exit.
  2. The root command starts from config.Default(). Cobra binds flags directly to the central config.Config.
  3. The command normalises derived toggles and validates output and logging formats. --list-events exits here and does not resolve an object or acquire kernel resources.
  4. The object initialiser resolves eBPF bytes using PROJECT_BPF_OBJECT, then the explicit configuration path, then the embedded dist/project.bpf.o. BTF resolution independently uses PROJECT_BTF_FILE, the configured path, then /sys/kernel/btf/vmlinux.
  5. The application runner loads policy files, validates their event names, creates one policy manager and, when configured, parses detector files and constructs one detector engine. dirty tree Policy metadata may first reduce the detector catalogue.
  6. An exact finite policy event allowlist may replace or intersect the CLI include set before any eBPF module is opened. Open-ended policy rules do not narrow collection.
  7. The runner creates the Zap diagnostic logger and passes the policy manager, detector engine and logger into the eBPF runtime constructor.
  8. The eBPF constructor validates object bytes and BTF path, translates logical event selection into physical probe specifications and dependencies, and creates output adapters. No kernel resource has yet been acquired.
  9. Init initialises the detector engine, configures libbpf diagnostics and opens a libbpf module from the resolved object bytes.
  10. If a selected cgroup attachment requires it, the runtime reuses an existing cgroup-v2 mount or creates a temporary managed mount.
  11. The probe registry disables autoload for registered, unselected program names. The module then performs relocation, verification and loading for programs that remain enabled.
  12. User space reads and patches the singleton config_map entry for the optional exact effective-UID filter.
  13. The runtime creates buffered Go channels, opens one libbpfgo perf reader for the events map with 1,024 pages, and starts it. A separate channel reports perf losses.
  14. The current runtime also initialises an events_map gate introduced for adjacent networking work. This is a real lifecycle dependency, but its packet semantics belong outside this chapter audit.
  15. Each selected probe is attached using the strategy stored in its registry specification. Links are retained in attachment order.
  16. The main loop waits for cancellation, raw perf records or loss notifications. Cancellation returns normally; record-local decoding and processing failures are logged without terminating the loop.
  17. The runner's deferred cleanup destroys links in reverse order, releases a runtime-created cgroup-v2 mount, closes the perf reader and closes the module.

Probe Planning and Registry Semantics

The probe registry is authoritative for production and attachment, not for binary decoding. A public specification provides a CLI-visible logical event name, a compiled program name, a hook and an attachment kind. Several specifications may share one logical event, which is how entry/return pairs and syscall families converge on one event schema. An internal specification remains attachable but is omitted from the public event set.

Dependency expansion is represented by impliedBy. A selected public event adds a support specification to the physical plan without adding its internal name to the logical event set. The resulting event set continues to control post-decode admission, while the specification slice controls autoload and attachment.

Selective-autoload boundary. Only program names represented in supportedProbes are considered for disabling. An unregistered program present in the eBPF object remains outside this control. Chapter 5 should say “unselected registered programs”, never “all unselected programs in the object”.

Lifecycle and Cleanup Findings

  • implemented Configuration and external definitions are prepared before the module is opened.
  • implemented A partially initialised Project is still closed because the runner installs defer project.Close() before calling Init.
  • implemented Links are destroyed in reverse attachment order and errors are accumulated with errors.Join.
  • implemented A pre-existing cgroup-v2 mount is never unmounted by the runtime; a runtime-created mount is tracked separately.
  • implemented SIGINT and SIGTERM cancel the shared context; the main loop treats cancellation as a normal stop.
  • gap The runner discards the error returned by Project.Close. Consequently, link-destroy or unmount failures are neither returned nor logged, despite documentation claiming observable cleanup conditions.
  • gap Init checks cancellation only at entry. Cancellation during a long object load or attach sequence does not interrupt those libbpf operations.
  • gap No direct tests exercise partial initialisation, reverse cleanup, signal cancellation, perf channel closure, cgroup mount ownership or attach failure.
  • gap The detector engine is initialised but exposes no corresponding close call in this lifecycle. This is acceptable only while detector resources remain ordinary Go state.

Defects and Qualification Requirements

Empty policy/CLI intersection fixed locally. NewProjectRunner now rejects an empty effective event set instead of passing it to probes.Select, where an empty include list means “all public events”. The regression is covered by TestNewProjectRunnerRejectsEmptyPolicyCLIIntersection. This correction is still pending commit.
  • The constructor defect identified in the previous audit is fixed in the pushed baseline.
  • Configured detectors do not independently expand the event collection plan. A detector may be constructed even when CLI/policy event selection omits an event it consumes; it will simply never receive that input. The policy selector validates required events for detectors selected by a policy, not for every CLI-configured detector.
  • Autoload control is registry-complete only if every relevant eBPF program is represented in the registry. No test compares the full object program catalogue with registry program names.
  • The raw config_map offsets are not mirrored by a typed Go structure and have no object-backed regression test.
  • The perf reader starts before the adjacent events_map initialisation and before attachment. This ordering is harmless for host producers because none is attached yet, but Chapter 5 should describe the actual order rather than saying all maps are configured before the reader opens.

Chapter 5 Runtime Section: Paragraph Plan

  1. Implementation boundary. Introduce the Go control plane as the concrete owner of configuration, object resolution, probe planning and resource lifetime; cross-reference Chapter 3 instead of repeating the architecture diagram.
  2. Outer bootstrap. Explain flag binding, normalisation, validation and the privileged-free --list-events branch.
  3. Object inputs. State the exact object and BTF precedence, including embedded bytes and the limits of embedding. Do not repeat general BTF/CO-RE theory from Chapter 2.
  4. Policy-derived scope. Explain only the concrete compilation of exact allowlists into the effective event set. Open-ended policy semantics and detector algorithms belong later in Chapter 5.
  5. Two registries, one plan. Describe the probe registry's concrete representation of public producers, internal dependencies and many-to-one logical events; cross-reference Chapter 3's conceptual definitions.
  6. Selective loading. Show that autoload is changed before BPFLoadObject, while explicitly limiting the claim to registered program names.
  7. Post-load resources. Describe the exact UID map patch, perf reader and loss channel. Mention the adjacent event-gate map only as an implementation dependency, without discussing networking.
  8. Attachment dispatch. Explain that one registry field selects the libbpfgo attach API. Use representative raw-tracepoint, kprobe and paired kretprobe examples rather than a hook catalogue.
  9. Ownership and failure boundaries. Distinguish fatal bootstrap failures from event-local errors, then state cancellation and reverse cleanup. The local runner correction now surfaces cleanup errors.
  10. Test boundary. Close with registry invariants that are unit-tested and lifecycle operations that still require object-backed or target-kernel tests. Evaluation results remain in Chapter 6.

Implementation Limitations for Chapter 5

  • Selective autoload depends on registry completeness and is not an object-wide discovery mechanism.
  • Object and BTF resolution is target-facing configuration, not a portability guarantee.
  • Attachment is fail-fast: the runtime does not continue with a partially attached observation domain.
  • The exact UID filter is a narrow map-configured admission control, not a compiled policy language.
  • Perf transport has finite capacity and explicit loss notifications; measured loss belongs in Chapter 6.
  • Cleanup attempts are ordered, and the local correction now logs and returns cleanup errors. Direct lifecycle tests are still missing.
  • Cgroup mount creation is conditional and privileged; it is not evidence of Kubernetes deployment or workload identity.

Acceptance Summary

The architecture described in Chapter 3 is recognisable in the implementation: user-space validation precedes kernel acquisition, logical events become a dependency-aware physical plan, autoload is configured before loading, one perf reader feeds the runtime, and a single owner closes links, conditional mounts, the reader and the module. The constructor and detector-selection changes are now present in the pushed baseline. The evidence remains strongest for pure selection and registry invariants; libbpf lifecycle operations still have no direct tests.

Chapter 5 can describe the current lifecycle after the three local corrections are committed. It should retain two qualifications: selective autoload is registry-bounded, and detector selection does not automatically expand the event scope. Cleanup errors are now surfaced by the local runner correction.
