Revised Structure

  1. sec:implementation-loader-registry: configuration, object/BTF resolution, logical selection, dependency expansion, selective autoload, attachment and shutdown.
  2. sec:implementation-decoder-registry: perf-record consumption, explicit context decoding, schema-directed indexed arguments and admission boundaries.
  3. sec:userspace-event-selection: ordered event admission, policy scope and the distinction between raw-event and alerts-only output.
  4. sec:implementation-policy-detector: YAML definitions, point and collective evaluation, bounded local correlation and ATT&CK metadata.
  5. sec:implementation-output-logging: presentation boundary, alert rendering and structured diagnostic logging.
  6. sec:implementation-containerisation: build and packaging boundary only.
  7. sec:user-space-implementation-summary: concise bridge to Chapter 6.

The retained and newly introduced subsection labels are subsec:implementation-yaml-definitions, subsec:implementation-point-collective, subsec:implementation-correlation-deduplication and subsec:implementation-attack-metadata.

Warnings and Follow-up

  • security_socket_sendmsg remains public in the current probe registry while lacking a public decoder schema. This is an implementation/test inconsistency outside the Chapter 5 host-runtime narrative; it should be corrected by making the support probe internal or by defining a matching public event and schema.
  • The current detector engine has no periodic production flush. Time-window expiry is evaluated when new relevant events are processed; this is described as a local implementation boundary, not as general complex-event processing.
  • There is no end-to-end test which exercises every attachment route against the target kernel. Registry tests detect source-level interface drift, not target-kernel hook availability.
  • The chapter deliberately excludes networking, cluster-wide correlation, enforcement and experimental results. These remain outside its implementation boundary.
