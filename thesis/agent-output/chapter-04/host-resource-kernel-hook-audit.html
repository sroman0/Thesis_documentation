2. Interpretation Rules

  • Syscall request path: a dedicated syscall entry tracepoint retains request arguments in args_map; the matching exit tracepoint emits one logical event with the kernel return value. A non-negative return generally indicates success, while a negative value is an errno.
  • Resolved semantic path: an LSM/VFS kprobe receives a kernel object such as struct file, dentry, vfsmount or VMA. It can expose resolved identity that the userspace request cannot, but an entry-only probe does not establish the final operation result.
  • State/lifecycle tracepoint: cgroup and module raw tracepoints describe the kernel lifecycle notification represented by that tracepoint. They do not carry a syscall return value.
  • Paired kernel function: selected kprobe/kretprobe pairs retain the entry object and emit at return, making the function result part of the event.

All events use the shared context and indexed argument buffer. Variable data are bounded: path reconstruction traverses at most 20 components; strings are bounded by 4096 bytes; string arrays inspect at most 38 elements; the event supports at most 32 indexed arguments; paired state stores seven machine-word slots. These are verifier and transport bounds, not claims of complete object capture.

4. Cross-Cutting Compatibility and Verifier Findings

  • Path and inode handling. common/filesystem.h reconstructs paths backwards in per-CPU scratch storage with a fixed 20-component loop. Disconnected dentries produce a marker. Inode change time selects among pre-6.6, 6.6--6.10 and later layouts through CO-RE field checks.
  • Cgroups. common/cgroups.h explicitly handles upstream pre-5.5 kernfs_node_id, the RHEL 8 hidden KABI field and the newer direct ID. Current-context lookup also distinguishes configured cgroup v1 from helper-based cgroup identity.
  • Architecture. The deployment target is x86-64 Rocky Linux 8.10, kernel 4.18. Compatible 32-bit syscall IDs are translated through a map in the raw path. Current-register fallback assumes 4 KiB pages, a 16 KiB kernel stack and no KASAN stack expansion.
  • Typed syscall tracepoints. The audited syscall families use target-specific typed tracepoint context structures rather than the generic raw dispatcher. Their portability therefore depends on the named tracepoints and field layouts existing on the deployment kernel.
  • VMA qualification. common/memory.h contains a bounded 35-level RB-tree VMA lookup and rejects kernels without mm_rb, but no audited host-memory hook calls that helper. Chapter 4 should not present that traversal as part of mmap, mprotect, pkey_mprotect or security_file_mprotect.
  • Transport and record bounds. All audited programs call events_perf_submit. The active implementation does not use the BPF ring buffer for these events.

5. Test and Documentation Evidence Assessment

The strongest automated evidence is structural rather than behavioural:

  • TestPublicProbesHaveDecoderSpecs and TestDecoderEventsAreExposedByPublicProbes enforce the public probe/schema relationship.
  • Family tests verify that one logical event expands to the expected number of physical probes, including six chmod, eight chown, four open, paired memory/namespace probes and paired dynamic-instrumentation probes.
  • pkg/events/spec_test.go enforces unique IDs/names and name-ID round trips.
  • Decoder tests cover the common context, long argument records, arrays, invalid UTF-8 and truncated fixed/array payloads. They do not provide event-by-event kernel emission tests.

documentation/implementation/hooks.md documents open, chmod/chown, memory syscalls, setns/unshare, cgroups, module lifecycle, BPF security hooks, kernel-read hooks, mount/umount and unlink. It currently lacks dedicated sections for security_inode_rename, security_inode_symlink, security_inode_mknod, security_mmap_file and security_file_mprotect. For those events, the C program, Go schema and registry tests are the authoritative evidence.

6. Claims the Thesis Must Not Make

  • Entry-only LSM probes do not prove that the checked operation succeeded or that a later security module did not deny it.
  • Vector addresses and counts from process_vm operations are metadata; no transferred process-memory payload is collected.
  • File and cgroup identifiers support local comparison. They do not reconstruct arbitrary process ancestry, persistent resource graphs or Kubernetes workload identity.
  • Module and instrumentation hooks expose selected lifecycle and registration surfaces. They do not prove kernel integrity, detect hidden modules, enumerate all hooks, or inspect handler code.
  • Kernel-read events do not copy the read buffer, calculate a digest or automatically pair the pre/post checkpoints.
  • CO-RE adapts known field layouts; it cannot supply missing symbols, tracepoints, helpers, permissions or verifier capabilities.
