7. Exact Content of Compressed Section 4.7

Section 4.7 must be one compact implementation section. It may use unnumbered paragraph headings, but must not retain the current four numbered conceptual subsections.

  1. Configuration boundary. Files and non-recursive directories are expanded deterministically; YAML is decoded into file schemas, converted into policy or detector definitions, validated, and then compiled into runtime objects. State explicitly that unknown YAML fields are not universally rejected and unsupported compact policy-filter forms are ignored during conversion.
  2. Policy admission. Scope is checked before alternative rules; exclusions and suppress matches take precedence. Exact finite policy allow-lists can reduce the event set before probe loading. Do not describe metadata-based detector catalogue selection unless it has first been committed, retested and adopted as the final baseline.
  3. Indexed point dispatch. Detector event names build an index once. Conditions and operators are normalised and numeric constants parsed before processing. Runtime supports equality, inequality, containment, membership, prefix, suffix, existence and numeric comparisons. Errors remain associated with one detector and do not stop other candidates.
  4. Collective transition. A stateful detector with more than one ordered step stores the next expected step, first-observation time and ordered evidence. Completion deletes the partial match before constructing the alert. Non-stateful multi-step definitions act as alternative event-specific condition groups rather than sequences.
  5. Correlation and bounds. Explain stable process identity (host PID plus start time), immediate-parent lookup only, device/inode resource identity without pathname fallback, non-zero local cgroup identity and ordered composite conjunction. Missing components produce no key; user_session is rejected. The default window is two seconds, the maximum five seconds, and the deadline starts at the first observation. Each detector retains at most 4,096 partial keys and one sequence per key; a repeated first step replaces that key and capacity pressure evicts the oldest first observation.
  6. Expiry and deduplication. Expiry is checked on addressed state and opportunistically pruned at intervals no longer than one second. Flush removes expired state without timeout alerts, but the main runtime does not schedule it periodically. Alert deduplication uses a five-second interval and a key derived from detector/output identity and the first evidence event; later collective evidence is not part of that key.
  7. Threat metadata. ATT&CK tactic and technique identifiers receive syntactic validation and complete detector metadata is copied to alerts. The implementation does not consult an external ATT&CK catalogue, infer mappings or establish complete technique coverage.

9. Claims and Numerical Limits Requiring Qualification

Claim or limitMandatory qualification
Target compatibilityClaim the audited Rocky Linux 8.10 kernel 4.18.0-553.137.1.el8_10.x86_64, not arbitrary Linux portability. Vendor backports require validation on the actual host.
BTF and CO-REThey adapt compatible data-layout differences; they do not provide absent hooks, helpers, symbols, program types, attachment paths, permissions or verifier acceptance.
Security hooksThe implementation attaches kprobes to security_* functions. These are observation points, not BPF-LSM programs, and entry-only records do not contain the eventual return decision.
Semantic stagesAttempt, mediation, committed state, successful transition and syscall return are distinct. A result field must be interpreted according to its syscall, especially setfsuid/setfsgid.
Event contextThe C/Go header is exactly 136 bytes. Its explicit field order is a maintained ABI, not a self-describing format.
Argument workspaceARGS_BUF_SIZE is 32,000 bytes per workspace, but perf submission transports only the populated variable record. The non-power-of-two offset fix is commit 163ad724....
Argument limitsThe generic temporary syscall structure has seven 64-bit slots; the general argument index ceiling is 32. String-array traversal and compact argument-array traversal have different bounds (38 and 15 on the C side); individual strings are bounded to 4,096 bytes.
PathsKernel path reconstruction is bounded to 20 components and 4,096-byte storage. It may produce partial or disconnected representations and is not a universal canonical-path guarantee.
Perf-event transportThere is one libbpfgo reader over a perf-event array with per-CPU ordering/loss characteristics. Do not claim a global total order or a ring-buffer fallback.
Decoder validationUnknown IDs, invalid indexes, truncation, oversized variable fields and invalid textual payloads fail. Missing arguments, duplicate indexes (last value wins) and trailing bytes are tolerated. The wire carries no independent type tag.
Registry consistencyGo tests relate public probes and decoder schemas, including multi-probe families. Numeric C and Go event IDs are not automatically compared across languages.
Kernel UID filterIt is one exact effective-UID equality guard. Go currently writes C-layout offsets 12 and 16 after a size check; no loaded-object readback integration test verifies those fields.
Collective stateTwo-second default, five-second maximum and 4,096 partial keys are per-detector implementation limits. State is local and process/resource/cgroup correlation is not a persistent process graph, arbitrary ancestry or cluster-wide CEP.
ExpiryPruning is event-driven and Flush is not periodically scheduled by the main loop. Idle expired entries may remain until another relevant event or an external flush.
DeduplicationThe five-second key includes only the first evidence event for collective alerts, so distinct completions sharing that first observation may be collapsed.
ATT&CKMetadata improves classification and traceability. Validation is syntactic; it does not infer mappings or establish correctness or complete coverage.
Container imageThe BPF object is embedded, but policy/detector YAML catalogues are not copied into the runtime image. The executable retains runtime dependencies on libc, libelf and zlib. No Kubernetes resources are implemented.
Performance and security effectDo not derive benchmark conclusions from implementation structure. The system observes and detects; it does not enforce, prevent attacks or provide contextual/cluster-wide anomaly detection.
