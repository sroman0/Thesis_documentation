Exact Limits and Qualifications That Must Remain

  • Policy and detector directories are scanned non-recursively; accepted YAML files are processed in deterministic filename order.
  • The YAML decoders are not configured for universal unknown-field rejection. Unsupported compact policy-filter forms are ignored during conversion rather than rejected.
  • Detector parsing validates structural metadata, referenced event names, performance bounds, ATT&CK identifier syntax and correlation compatibility. Operators and expected operands are compiled only when a parsed definition is instantiated as a runtime detector.
  • The compiled operators are equality, inequality, containment, membership, prefix, suffix, existence, non-existence, greater-than and less-than. Numeric operands and membership lists are prepared before event processing.
  • The dispatcher is indexed by logical event name. A detector declaring no event names is treated as a wildcard and is invoked for every event. One detector failure does not prevent the other candidates from running.
  • An ordered collective path exists only when the definition is marked stateful and has more than one compiled step. Otherwise multiple steps behave as alternatives for individual events.
  • The omitted stateful window defaults to two seconds and the validated maximum is five seconds. The deadline is measured from the first matched step and is not extended when later steps advance the sequence.
  • Each detector retains at most 4,096 incomplete correlation keys and one partial sequence per key. A new first-step match for an existing key replaces the older partial sequence; admitting a new key at capacity evicts the state with the oldest first-observation time.
  • State stores the next expected step, the first-observation time and the ordered evidence accumulated so far. Completion deletes the partial state before constructing the alert.
  • Process identity is host PID plus process start time. Process-tree lookup adds only the immediate parent identity; it does not traverse ancestry. Resource identity is device plus inode and has no pathname fallback. Cgroup identity requires a non-zero local cgroup ID. Composite correlation is an ordered conjunction, so a missing component prevents key construction. The unavailable user_session strategy is rejected rather than approximated with UID.
  • Unrelated expired sequence entries are scanned opportunistically at an interval no greater than one second. The addressed state is checked directly on every relevant event. Explicit flush removes expired states without timeout alerts, but the main runtime does not currently schedule periodic detector flushes; idle expired entries may therefore remain allocated until later activity or an external flush.
  • Alert deduplication runs after detector evaluation with a five-second interval. Its key contains detector ID, title and severity plus only the first evidence event's name, PID, UID, command and ordered arguments. Timestamps, thread IDs and later collective evidence are excluded. Deduplication state older than twice the interval is pruned when deduplication runs. Suppression does not rewrite raw events or collective state.
  • ATT&CK validation checks only non-empty tactic IDs of the form TA#### and technique IDs of the form T#### or T####.###. Unmapped detectors remain valid. The runtime neither loads an external ATT&CK catalogue nor verifies the semantic correctness or coverage of a mapping.
  • A matching detector copies its complete configured threat metadata and retained source-event evidence into the alert.

Claims Dependent on Uncommitted Code

The following claims describe the audited working tree but not commit ae65344. They should be excluded from the definitive Chapter 4 baseline until committed and re-audited.

  • A policy may contain a detectors selector with include/exclude criteria for detector IDs, severity, ATT&CK tactics, ATT&CK techniques, tags and statefulness.
  • Values within one detector-selector field use OR semantics, populated fields combine by AND, and local exclusions remove matching candidates.
  • Suppress policies are rejected when they attempt to select detectors.
  • Selections from multiple eligible policies are combined as a union, explicit unknown detector IDs are rejected, and a selector that matches no detector fails bootstrap.
  • A selecting policy is checked for coverage of every event consumed by the selected detector.
  • The runtime parses the complete detector catalogue, applies policy selection, and constructs detector instances and state only for the selected definitions.
  • Runtime diagnostics distinguish available detector definitions from loaded detector instances and report whether policy selection was applied or skipped.
  • The preset rules/policies/mitre-privilege-collective.yaml exists as a policy example.

The unrelated local changes in probe classification, runtime attachment, build commands and README material do not change the committed detector-state mechanisms assessed here, but they reinforce the need to record a clean commit before final Chapter 4 acceptance.

Editorial Conclusion

Section 4.7 can satisfy the implementation objective in approximately six to eight compact paragraphs plus one primary listing. Its distinctive contribution is not another conceptual account of policies and detectors, but a precise account of conversion, precompilation, indexed dispatch, finite state transitions, exact local keys, cleanup and deduplication limits, and metadata preservation. Removing the four conceptual subsections will reduce repetition while preserving every implementation fact needed by Chapters 4 and 5.
