Evidence Reconciliation

  • Current source and tests take precedence over audit prose and historical documentation.
  • The active kernel transport is exclusively perf-event based. No retained BPF ring-buffer implementation is present.
  • The Docker runtime image currently contains the executable with its embedded eBPF object, but not the policy and detector catalogues.
  • The supplied docker-run target mounts host BTF and bpffs but does not use its declared tracefs/debugfs mount set.
  • Policy-driven detector selection and the latest network support-probe classifications are current-tree behaviour, not part of the recorded commit.
  • The C and Go common contexts share an explicit 136-byte layout. Event/probe registry consistency is tested in Go, but C and Go event constants are not compared automatically.
  • The 32,000-byte argument buffer uses explicit bounds handling; commit 163ad724 corrected the former non-power-of-two mask defect.

Binding Editorial Decisions

  • Use British English and the canonical “user space”/“user-space” forms.
  • Explain each mechanism once; use cross-references for design rationale already owned by Chapters 2 and 3.
  • Use representative process and host-security hook families; move the complete catalogue to Appendix A.
  • State implementation limits numerically where verified, but reserve adequacy and performance conclusions for Chapter 5.
  • Do not describe the system as enforcement, general anomaly discovery, persistent graph correlation or cluster-wide analysis.
  • Do not use the internal product name.
