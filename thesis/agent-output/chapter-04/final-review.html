Claims Verified Against Current Code and Tests

  • The common C and Go event context is 136 bytes.
  • The active transport is a perf-event array consumed by one libbpfgo perf reader.
  • The argument workspace is 32,000 bytes and is kept outside the eBPF stack in per-CPU storage.
  • Paired operations retain up to seven entry arguments using event identity and thread identity.
  • The decoder is schema-directed but not canonical: missing arguments and duplicate indexes are accepted, duplicate indexes use the latest value, and trailing bytes are not required to be consumed.
  • Commit 163ad724a65ec8c701dc816fe87f174eeec51275 replaced invalid mask-based offset handling for the non-power-of-two argument buffer and added long-record regression evidence.
  • The exact kernel UID filter uses a singleton configuration map, an enable field at byte offset 12 and a UID field at byte offset 16.
  • Collective detector state is detector-local, limited to 4,096 incomplete keys, and bounded by a short window; runtime flush is available but not periodically scheduled by the main loop.

5. Material That Belongs in Chapter 5

  • Do not quantify or imply the performance improvement of deferred enrichment or the UID filter in 4.2 or 4.6. Chapter 4 may state only which operations are skipped.
  • Do not infer efficiency from selective autoload. Chapter 4 may state that unrelated registered programs are not loaded; verifier-time and CPU effects require measurement.
  • Do not promote the operational audit's unexecuted Docker claims into validated deployment results. Image build, privileged execution and hook coverage inside the container belong to functional evaluation.
  • The 4,096-state and five-second deduplication values are implementation parameters and belong in Chapter 4. Their adequacy, memory impact, false-positive effect and saturation behaviour belong in Chapter 5.
  • The long-record regression is valid implementation evidence. Broader claims about decoder robustness require the Chapter 5 functional test matrix.
