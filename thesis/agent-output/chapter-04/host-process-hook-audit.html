Shared Construction Mechanisms

All direct producers initialise the same per-CPU event workspace and later submit a context plus indexed argument buffer through the perf-event map. Context enrichment uses the LRU task and process maps. Large event, scratch and path data therefore remain in maps rather than on the restricted BPF stack. Entry/return events additionally use args_map, a 10,240-entry hash keyed by logical event ID and current TID. Entry state is replaced on a repeated key and normally deleted by the matching return program.

The main verifier-facing bounds are shared: at most 32 argument indexes, a 32,000-byte argument buffer, fixed explicit copies from the seven-slot temporary argument structure, and an in-line clamp before perf submission. Executable argument vectors are unrolled to at most 38 elements; each string is bounded and an ellipsis marks truncation. Kernel paths are reconstructed using bounded per-CPU storage and a maximum of 20 components.

CO-RE relocates kernel-structure reads, but manually declared syscall tracepoint contexts still encode the x86-64 Rocky Linux 4.18 field widths. The implementation is therefore deliberately target-specific at this edge. Common task context also contains CO-RE branches for task start-time field evolution. Credential capability conversion selects either the older pair of 32-bit words used by the target or a newer 64-bit layout.

Cross-Event Semantic Findings

  • Several probes, one event: process_execute_failed is built by four exec-family tracepoint programs. Each of clone, the eight set-ID events, ptrace and prlimit64 uses an entry/exit pair. fork and vfork also register pairs, although only their exit programs contribute to the record.
  • Creation stages: fork/vfork/clone report syscall completion from the caller's perspective; sched_process_fork reports the child task that actually exists. They are complementary, not aliases.
  • Exec stages: execve/execveat are attempts; security_bprm_check is executable validation; security_bprm_creds_for_exec is credential preparation; sched_process_exec is successful image replacement; process_execute_failed is an explicit negative syscall result.
  • Credential stages: set-ID syscall events preserve request and return; security_task_fix_setuid observes proposed UID credentials at mediation; commit_creds observes the installed before/after state and also covers non-syscall credential paths.
  • Limit stages: security_task_setrlimit exposes proposed values at mediation but no outcome; prlimit64 exposes syscall completion but currently retains only user pointers to the limit structures.
  • Naming correction: “security_task_fix_setuid/security_task_fix_setgid” must not be used as if both public events existed. The implementation and target expose only security_task_fix_setuid; GID changes are observed through syscall events and commit_creds.

Test and Evidence Gaps

The tests strongly cover the registry contract: public probe names must have decoder schemas, decoder events must be publicly exposed, internal probes must remain hidden, and selected multi-probe families must attach the expected number of programs. Decoder tests cover typed arguments, string arrays, credential snapshots, truncation and the long security_bprm_check record.

There are no automated tests in the inspected packages that execute these eBPF programs on the target kernel and assert their exact emitted arguments or stage semantics. There are also no event-specific decoder fixtures for every row above, no automatic comparison between C event constants and Go IDs, and no test proving cleanup after every missed entry/return pairing. Chapter 4 may describe the implementation; Chapter 5 must own runtime validation claims.
