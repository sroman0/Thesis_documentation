Cross-Pod Performance Evaluation

PRIMARY RESULT: PASS. Across three filtered runs, mean monitor CPU was 0.46% of one core. Every monitored exploit recovered the flag and generated the complete alert, with no reported event loss or Pod restart.

Method

The benchmark ran on the same single-node Minikube deployment used for the functional evaluation. Three rotated rounds compared the canonical UID-filtered monitor, the same monitor without kernel UID filtering, and a control in which the monitor DaemonSet was removed. Each run executed the 1,793-worker AES-beta exploit once, without automatic retry.

A sampler outside the monitor read cgroup-v1 CPU, memory, RSS and PID counters once per second. Container CPU is reported as a percentage of one core. Node CPU is the utilisation of the complete two-CPU Minikube node. Only samples within the recorded workload interval enter the summaries.

The filtered mean was below the predefined 5% threshold in every run. Relative to the unfiltered profile, early UID admission reduced measured monitor user-space CPU by 91.97%. All six monitored runs recovered the flag and produced one complete four-event alert; loss diagnostics and restart deltas were zero.

Interpretation Boundary

The primary metric covers the monitor container's user-space cgroup. It does not include kernel execution time charged to observed tasks and must not be presented as total system overhead. The AES-beta brute force kept the two-CPU node close to saturation: mean node utilisation was 93.99% filtered, 94.49% unfiltered and 93.77% in the control. Duration differences are therefore descriptive and do not establish causal overhead.

No-monitor audit note. Immediately after each DaemonSet deletion, the saved Kubernetes snapshot still showed the former monitor Pod as Terminating. The workload began after a ten-second warm-up, but the evidence did not independently record the Pod's final deletion time. The three controls are preserved, but their duration is not used for an overhead claim. The profile script has since been changed to wait for and verify complete Pod disappearance.
