Cross-Pod Minikube Experiment: Final Report

FINAL VERDICT: PASS WITH STATED LIMITATIONS

Objective

The experiment evaluates the monitoring tool in a self-contained, single-node Kubernetes laboratory. It asks whether a privileged eBPF monitor can observe and detect the AES-beta exploitation sequence when the monitor, vulnerable target and attack trigger run in three independent Pods, and whether the operational monitor remains below its 5% user-space CPU target.

Experimental Scope

PropertyEvaluated configuration
PlacementDaemonSet monitor, one-replica target Deployment and standalone trigger Pod on one Minikube node
NetworkTrigger Pod to ClusterIP Service to target Pod on TCP/1337
IsolationDistinct Pod UIDs, IPs, container identities and pod cgroups; hostPID: false
MonitoringTarget UID 10001, exact kernel UID filter, three selected events and one collective AES-beta detector

Architecture and Method

The target exposed TCP/1337 through a ClusterIP Service. The non-root trigger reached that Service from a separate Pod, while the privileged monitor ran as a DaemonSet Pod and attached eBPF programs to the shared node kernel. All Pods retained hostPID: false. The synthetic flag Secret was mounted only in the target.

After deployment, the procedure verified Pod identity, IP and cgroup separation, Service routing, target telemetry visibility and exact-UID admission. It then executed three benign controls and three exploit runs without automatic retry. Application results, detector output, loss diagnostics and restarts were evaluated independently.

Observed Anomalies

The first benign run waited behind the non-protocol Phase 5 connection until the target timeout. Its 138,181 ms duration is retained but excluded from performance interpretation. The first two exploit clients recovered the flag and triggered complete alerts but returned status 1 because the reused client expected a THESIS{...} flag while this laboratory generated openECSC{...}. The first correction was malformed by Bash parameter expansion; the corrected literal pattern was verified by the third run. No failed run was replaced.

Supported Claims

In the evaluated single-node Minikube environment, the privileged monitoring Pod observed and detected the AES-beta exploitation sequence generated in the target Pod while the client executed from a separate trigger Pod. Observation remained node-local and was obtained from eBPF hooks attached to the kernel shared by the three Pods.

Unsupported Claims and Limitations

  • The experiment does not demonstrate cross-node or cluster-wide detection.
  • The monitor remains privileged; a production least-privilege profile was not established.
  • UID 10001 is an experimental admission key, not a Kubernetes workload identity.
  • The evaluation is scenario-specific and does not establish general detector coverage or production readiness.
  • The experiment evaluates observation and detection, not enforcement.
  • The CPU result measures the monitor container's user-space cgroup and is not total kernel or system overhead.
  • The node was close to saturation during the brute-force workload, so duration differences are descriptive.
  • The no-monitor snapshots did not independently prove final monitor-Pod deletion before workload start; their durations are not used for a causal overhead claim.

Relevance for Chapter 6

Chapter 6 can use this experiment as its only evaluation narrative: laboratory topology, controlled workload, functional results and replicated monitor measurements on the same node. The filtered result is the primary performance finding; the unfiltered result demonstrates the effect of early UID admission. The delayed benign run and no-monitor controls must not be used as workload-overhead evidence.

PASS WITH STATED LIMITATIONS. The topology, Service path, target visibility, detector behaviour and filtered monitor CPU target are supported by preserved evidence. The claim remains limited to this single-node, privileged-monitor and scenario-specific environment; no total-system or cross-node performance claim follows.
