Cross-Pod Minikube Laboratory

This document preserves the manual commands used to reconstruct and test the AES-beta laboratory. The monitor, target and trigger run in separate Pods on one Minikube node. Commands are executed from /home/simone/project/demo_project.

Reading rule. Expected results are acceptance conditions. They must not be reported as observations unless the corresponding command has actually been executed.

1. Enter the Repository

cd /home/simone/project/demo_project

cd selects the repository as working directory; all later paths are relative to it.

2. Start Minikube

minikube status -p cross-pod

-p cross-pod selects the isolated laboratory profile. If it does not exist, create it:

minikube start -p cross-pod \
  --driver=docker \
  --kubernetes-version=v1.30.0 \
  --cpus=2 \
  --memory=4096

--driver=docker runs the node as a Docker container. The remaining options fix the Kubernetes version and allocate two CPUs and 4096 MiB.

kubectl --context cross-pod get nodes -o wide

--context prevents access to another cluster; -o wide includes kernel and runtime information. The node must be Ready.

3. Build the Updated Monitor Image

docker build \
  --network=host \
  --tag demo-project-ebpf:latest \
  .

--network=host supplies the host network during the build, --tag assigns the manifest's image name, and . is the build context.

docker run --rm \
  --entrypoint /bin/sh \
  demo-project-ebpf:latest \
  -c 'cat /etc/project/policies/aes-beta-process-observation.yaml'

The temporary container is removed by --rm. The overridden shell entry point prints the packaged policy, which must include sched_process_exec, open and security_file_open.

4. Build Target and Trigger Images if Necessary

docker image inspect aes-beta-target:local
docker image inspect aes-beta-trigger:local

These commands verify whether the local tags exist. Before rebuilding, the verified openECSC artefacts must be present under k8s/minikube-ctf/.build/upstream/.

docker build \
  --file k8s/minikube-ctf/images/target/Dockerfile \
  --tag aes-beta-target:local \
  k8s/minikube-ctf

docker build \
  --file k8s/minikube-ctf/images/trigger/Dockerfile \
  --tag aes-beta-trigger:local \
  k8s/minikube-ctf

--file selects the component Dockerfile, --tag assigns its local name, and the final path supplies the shared build context.

5. Load the Images into Minikube

minikube image load -p cross-pod \
  --overwrite=true demo-project-ebpf:latest

minikube image load -p cross-pod \
  --overwrite=true aes-beta-target:local

minikube image load -p cross-pod \
  --overwrite=true aes-beta-trigger:local

image load copies each host image into the node. --overwrite=true replaces an older image using the same tag.

minikube image ls -p cross-pod |
grep -E 'demo-project-ebpf|aes-beta-target|aes-beta-trigger'

The pipe filters the node image list; -E enables alternatives in the expression. All three names must be present.

6. Validate the Manifests and Create the Namespace

kubectl --context cross-pod apply \
  --dry-run=client \
  -f k8s/minikube-ctf-cross-pod/manifests/

--dry-run=client validates the files locally without creating resources. -f selects the manifest directory.

kubectl --context cross-pod apply \
  -f k8s/minikube-ctf-cross-pod/manifests/namespace.yaml

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  delete configmap project-monitor-cross-pod-policy \
  --ignore-not-found=true

The first command creates the dedicated namespace. The second removes the obsolete policy ConfigMap; -n selects the namespace and --ignore-not-found=true makes absence harmless. The policy now resides in the monitor image.

7. Create the Detector ConfigMap

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  create configmap project-monitor-cross-pod-detector \
  --from-file=aes-beta-command-execution.yaml=k8s/minikube-ctf/detectors/aes-beta-command-execution.yaml \
  --dry-run=client \
  -o yaml |
kubectl --context cross-pod apply -f -

--from-file stores the detector with its expected filename. --dry-run=client -o yaml renders YAML, and the pipe sends it to apply -f -, where the dash means standard input.

8. Create the Synthetic Flag Secret

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  create secret generic aes-beta-cross-pod-flag \
  --from-literal='flag=openECSC{ebpf_cross_pod_evaluation}' \
  --dry-run=client \
  -o yaml |
kubectl --context cross-pod apply -f -

--from-literal defines the synthetic flag. Rendering and applying the Secret makes the command repeatable. The target Deployment is the only workload that mounts it.

9. Deploy the Workloads

kubectl --context cross-pod apply \
  -f k8s/minikube-ctf-cross-pod/manifests/target-deployment.yaml \
  -f k8s/minikube-ctf-cross-pod/manifests/target-service.yaml \
  -f k8s/minikube-ctf-cross-pod/manifests/trigger-pod.yaml \
  -f k8s/minikube-ctf-cross-pod/manifests/monitor-daemonset.yaml

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  rollout restart daemonset/project-monitor-cross-pod

The manifests create the target Deployment, ClusterIP Service, trigger Pod and monitor DaemonSet. rollout restart forces a fresh monitor Pod so it uses the newly loaded image.

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  rollout status deployment/aes-beta-target-cross-pod \
  --timeout=180s

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  rollout status daemonset/project-monitor-cross-pod \
  --timeout=180s

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  wait --for=condition=Ready \
  pod/aes-beta-trigger-cross-pod \
  --timeout=180s

rollout status waits for controller-managed resources; wait checks the standalone trigger directly. The timeout prevents indefinite blocking.

10. Verify the Topology

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  get pods -o wide

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  get pods \
  -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,IP:.status.podIP,NODE:.spec.nodeName,HOST_PID:.spec.hostPID,RESTARTS:.status.containerStatuses[0].restartCount'

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  get service,endpointslice -o wide

The three Pods must have different UIDs and IPs but the same node. HOST_PID must be empty or false and restart counts should be zero. The EndpointSlice must route the Service to the target Pod on TCP/1337.

11. Verify the Policy Used by the Monitor

MONITOR=$(kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  get pod \
  -l app.kubernetes.io/component=monitor \
  -o jsonpath='{.items[0].metadata.name}')

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  exec "$MONITOR" -- \
  cat /etc/project/policies/aes-beta-process-observation.yaml

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  get pod "$MONITOR" \
  -o jsonpath='{.spec.containers[0].args}'

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  logs "$MONITOR" --timestamps=true

The label query resolves the current Pod name. exec -- reads the policy from the running container. The JSONPath query prints the effective arguments, which must reference the packaged policy. Timestamped logs must not contain policy, YAML, eBPF loading or attachment errors.

12. Follow and Preserve Monitor Output

Run this in a separate terminal and leave it active:

mkdir -p /tmp/cross-pod-manual-evidence

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  logs -f daemonset/project-monitor-cross-pod \
  --timestamps=true |
tee /tmp/cross-pod-manual-evidence/monitor.log

logs -f follows new monitor records. tee displays and stores the same timestamped stream.

13. Run the Benign Control

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  exec aes-beta-trigger-cross-pod -- \
  env RUN_ID=benign-manual-01 \
  /opt/trigger/run-benign

exec runs the benign client in the trigger Pod. RUN_ID identifies the run. It must complete successfully without producing the AES-beta detector alert.

for run in 01 02 03; do
  kubectl --context cross-pod \
    -n ebpf-ctf-cross-pod \
    exec aes-beta-trigger-cross-pod -- \
    env RUN_ID="benign-manual-${run}" \
    /opt/trigger/run-benign
done

The loop performs three controls with distinct identifiers.

14. Run the Exploit

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  exec aes-beta-trigger-cross-pod -- \
  env \
  RUN_ID=exploit-manual-01 \
  'FLAG_PATTERN=^openECSC\{[A-Za-z0-9_-]+\}$' \
  /opt/trigger/run-exploit

The quoted FLAG_PATTERN validates the synthetic flag without local shell expansion. A successful run reports 1,793 workers and recovers openECSC{ebpf_cross_pod_evaluation}.

sched_process_exec  -> /bin/sh
sched_process_exec  -> /bin/cat
security_file_open  -> /opt/aes-beta/flag
open                -> flag with returnValue >= 0

The alert must contain this ordered evidence, detector ID aes-beta-command-execution and severity high.

for run in 01 02 03; do
  kubectl --context cross-pod \
    -n ebpf-ctf-cross-pod \
    exec aes-beta-trigger-cross-pod -- \
    env \
    RUN_ID="exploit-manual-${run}" \
    'FLAG_PATTERN=^openECSC\{[A-Za-z0-9_-]+\}$' \
    /opt/trigger/run-exploit
done

The loop executes three separately identified exploits. Failures must be retained rather than silently retried.

15. Inspect the Results

Stop the log follower with Ctrl+C, then run:

grep '"detector_id":"aes-beta-command-execution"' \
  /tmp/cross-pod-manual-evidence/monitor.log

grep -Ei 'lost|perf.*loss' \
  /tmp/cross-pod-manual-evidence/monitor.log

kubectl --context cross-pod \
  -n ebpf-ctf-cross-pod \
  get pods \
  -o custom-columns='NAME:.metadata.name,READY:.status.containerStatuses[0].ready,RESTARTS:.status.containerStatuses[0].restartCount'

The first grep extracts detector alerts. The second uses case-insensitive extended matching to find loss diagnostics; no match is expected. The final query checks readiness and restarts.

Expected acceptance: three successful benign runs with no AES-beta alert; three flag recoveries with three complete collective alerts; zero Pod restarts and no reported loss.

16. Cleanup

kubectl --context cross-pod \
  delete namespace ebpf-ctf-cross-pod

minikube stop -p cross-pod

Namespace deletion removes only the experiment resources. minikube stop preserves the cluster profile and loaded images. Use minikube delete -p cross-pod only to remove them permanently.
