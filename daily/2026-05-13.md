# 2026-05-13 - Reader duale ring buffer/perf buffer e filtro per comm

## Obiettivo

Aggiornare il runtime alla nuova versione del tool, in cui lo userspace non
legge piu' solo la ring buffer ma inizializza anche il perf buffer usato dagli
hook networking. Questo riduce la distanza rispetto a Tracee e risolve il
blocco principale emerso dopo il merge del branch networking.

## Attivita' svolte

- Analizzata la nuova versione di `demo_project/pkg/ebpf/project.go`.
- Verificato che `Project.Init()` inizializza ora due canali kernel/userspace:
  - ring buffer `events_ringbuf`;
  - perf buffer `events`.
- Verificato che `Project.Run()` ascolta entrambi i canali nello stesso
  `select`.
- Introdotto un handler comune `handleRawEvent(raw []byte)` per decodifica,
  filtro eventi, filtro command name e stampa.
- Verificato il nuovo filtro userspace `--comms`, salvato in
  `Events.FilterComms`.
- Verificato che il Makefile include il target `filtered`, utile per lanciare
  rapidamente il tool su `security_socket_connect`.
- Aggiornata la documentazione per rimuovere il limite precedente secondo cui
  gli eventi networking su perf buffer non potevano apparire nell'output.

## Differenza rispetto alla versione precedente

Prima:

```text
kernel ring buffer events_ringbuf -> Go InitRingBuf -> decoder/output
kernel perf buffer events        -> non letto dallo userspace
```

Ora:

```text
kernel ring buffer events_ringbuf -> Go InitRingBuf  \
                                                   -> handleRawEvent -> decoder/output
kernel perf buffer events        -> Go InitPerfBuf  /
```

Questa modifica rende il runtime capace di ricevere sia gli eventi
process/security che usano `events_ringbuf_submit`, sia gli eventi networking
che usano `events_perf_submit`.

## Filtro `--comms`

E' stato aggiunto un filtro userspace sul nome comando (`comm`):

```bash
make run ARGS="--events task_rename,sched_process_exec,sched_process_exit --comms ls,whoami --output table"
```

Il filtro viene applicato dopo la decodifica dell'evento:

1. decode raw event;
2. verifica `--events` / `--drop-events`;
3. verifica `--comms`;
4. stampa.

Questo filtro non riduce ancora il lavoro lato kernel, ma rende piu' leggibile
l'output durante demo e debug.

## Note tecniche

- Il perf buffer viene inizializzato con `InitPerfBuf("events", ..., 1024)`.
- Il lost channel del perf buffer e' al momento `nil`, quindi gli eventi persi
  non vengono ancora conteggiati lato userspace.
- Ring buffer e perf buffer restano entrambi presenti. La scelta finale potra'
  essere:
  - mantenere il modello duale durante la transizione;
  - migrare tutto a perf buffer per avvicinarsi a Tracee;
  - migrare tutto a ring buffer solo se la compatibilita' Rocky 4.18 resta
    affidabile.
