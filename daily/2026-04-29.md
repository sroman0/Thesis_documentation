# 2026-04-29 - Loader eBPF, verifier e struttura documentazione

## Obiettivo della giornata

Portare il progetto da uno skeleton CLI/userspace a un runtime capace di:

- leggere l'oggetto eBPF compilato;
- caricare la collection nel kernel;
- aprire la ring buffer;
- attaccare i programmi eBPF agli hook;
- restare in esecuzione drenando gli eventi.

## Cosa e' stato fatto

### Compilazione eBPF

Comando usato:

```bash
clang -g -O2 -target bpf -D__TARGET_ARCH_x86 -I pkg/ebpf/c \
  -c pkg/ebpf/c/project.bpf.c -o pkg/ebpf/c/project.bpf.o
```

Risultato: l'oggetto `project.bpf.o` viene generato correttamente.

### Startup userspace

E' stata introdotta una fase di inizializzazione che prepara la config prima di creare il runner:

- risolve il path dell'oggetto eBPF;
- risolve il path BTF;
- legge i byte dell'oggetto;
- passa la config pronta al runtime.

File rilevanti:

- `demo_project/pkg/cmd/initialize/bpfobject.go`
- `demo_project/pkg/cmd/cobra/cobra.go`
- `demo_project/cmd/project/cmd/root.go`

### Runtime eBPF Go

E' stato introdotto `demo_project/pkg/ebpf/project.go`.

Responsabilita':

- `New`: costruzione runtime;
- `Init`: load collection, ring buffer, attach programmi;
- `Run`: loop di lettura ring buffer;
- `Close`: cleanup link, ring buffer, collection.

### Attach hook

Sono stati aggiunti attach espliciti per:

- raw tracepoint:
  - `sched_process_fork`;
  - `sched_process_exec`;
  - `sched_process_exit`;
  - `task_rename`;
- kprobe:
  - `cap_capable`;
  - `security_task_setrlimit`;
  - `security_settime64`;
  - `security_task_prctl`.

Questa scelta rispecchia il pattern di Tracee, anche se in forma MVP e con `cilium/ebpf`.

## Problemi incontrati

### Memlock

Errore iniziale:

```text
map create: operation not permitted (MEMLOCK may be too low)
```

Mitigazione:

```go
rlimit.RemoveMemlock()
```

### Verifier e offset dinamici

Diversi errori del verifier indicavano:

```text
invalid access to map value, value_size=4280 off=65664
```

Interpretazione:

- il verifier vedeva `args_buf.offset` come potenzialmente fino a `65535`;
- gli accessi a `args[...]` risultavano quindi potenzialmente fuori dalla scratch map.

Mitigazione:

- slot fissi per argomenti scalari;
- slot fissi per stringhe;
- size esplicitamente bounded prima di `bpf_ringbuf_output`.

## Stato raggiunto

Il comando:

```bash
sudo go run ./cmd/project --bpf-object pkg/ebpf/c/project.bpf.o
```

arriva a:

```text
project runtime started ...
```

senza errori di load e senza errori del verifier.

Non stampa ancora alert perche':

- il loop Go legge i record dalla ring buffer;
- non li decodifica;
- non li stampa;
- non esiste ancora una detection logic.

## Prossimi passi

record, err := p.events.Read()
