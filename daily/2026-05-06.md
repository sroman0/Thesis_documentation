# 2026-05-06 - Oggetto eBPF embedded nel binario Go

## Obiettivo

Eliminare la necessita' di passare manualmente `--bpf-object` a ogni avvio del
tool, seguendo il pattern di Tracee: l'oggetto eBPF viene compilato prima e poi
incluso nel binario Go tramite `go:embed`.

## Implementazione

E' stato aggiunto `demo_project/embedded-ebpf.go`:

```go
package demo_project

import "embed"

//go:embed dist/project.bpf.o
var BPFBundle embed.FS
```

Il Makefile ora genera l'oggetto in:

```text
dist/project.bpf.o
```

I target `build`, `test`, `run`, `test-flag` e `run_table` dipendono da `bpf`,
cosi' il file embedded esiste prima della compilazione Go.

## Loader

`pkg/cmd/initialize/bpfobject.go` ora usa questa priorita':

1. `PROJECT_BPF_OBJECT`, se impostata;
2. `--bpf-object`, se passato;
3. oggetto embedded `dist/project.bpf.o`.

Quando usa l'oggetto embedded, `cfg.BPFObjPath` viene valorizzato come:

```text
embedded:dist/project.bpf.o
```

`cfg.BPFObjBytes` contiene comunque i byte dell'oggetto eBPF, quindi il runtime
`pkg/ebpf/project.go` non cambia.

## Differenza rispetto a prima

Prima:

```bash
sudo go run ./cmd/project --bpf-object pkg/ebpf/c/project.bpf.o
```

Ora:

```bash
make run
```

Oppure:

```bash
make build
sudo /tmp/project
```

Il path esplicito resta supportato per debug:

```bash
sudo go run ./cmd/project --bpf-object /tmp/project.bpf.o
```

## Verifiche

Comandi eseguiti:

```bash
make bpf
GOCACHE=/tmp/go-build go test ./...
go run ./cmd/project --help
go build -o /tmp/project ./cmd/project
```

## Note

Con `go:embed`, `dist/project.bpf.o` deve esistere al momento della compilazione
Go. Per questo i target Makefile principali dipendono da `bpf`.
